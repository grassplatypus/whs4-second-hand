# 워크로그 — 프론트엔드 완성 단계

작성일: 2026-07-25 (작업 자체는 7/24 심야~7/25 새벽)

기록 원칙: 무엇을 / 왜 / 어떻게 / 남은 것.

---

## 0. 왜 이 단계가 필요했나

#0~#7로 백엔드·API·보안·비즈니스 로직은 완성돼 있었고 테스트도 통과했지만, 브라우저로 직접 열어 보니 **제품이라고 하기 어려운 상태**였다. 원인은 분명했다.

- E2E가 페이지를 **URL로 직접** 열어 검사했다. 그래서 홈에 링크가 하나도 없어도, 로그인 후 상단 메뉴가 바뀌지 않아도 전부 통과했다.
- 각 화면은 "그 화면의 기능"만 갖췄고, 화면을 잇는 앱 셸(내비게이션·랜딩·에러 화면)과 시각적 일관성은 아무도 소유하지 않았다.

즉 **로직은 맞고 제품은 미완성**이었다. 이 단계는 그 간극을 메운 기록이다.

## 1. 어떻게 진행했나

1. **전면 검토 1차** — 6개 관점(클라이언트 런타임·UX 완성도·인증 플로·도메인 정합·보안·i18n/접근성)으로 병렬 리뷰 후 각 발견을 적대적으로 검증 → **확정 결함 36건**.
2. **기반 정리** — 공용 UI 키트, 앱 셸, 전역 에러/404/로딩, 폰트·시간대 등 "모두가 쓰는 것"부터 고쳤다.
3. **슬라이스 병렬 완성** — 인증·프로필 / 상품 / 채팅 / 에스크로·관리자를 각각 독립 작업공간에서 완성 후 병합.
4. **전면 검토 2차** — 레이아웃·정렬·간격·컴포넌트 일관성·스크롤바 + 서버 입력 검증·우회 + 기능 완성도 관점 → **확정 결함 30건**.
5. **요청 기능 추가** — 사용하며 나온 요구(프로필 사진, 약속, 후기, 숨기기, 신고 사유 선택, 읽음/안읽음, 방 나가기, 민감정보 탐지 등)를 그때그때 반영.
6. **최종 검토 + 검증 + 문서화**.

## 2. 고친 것 중 눈에 띄는 것들

- **글꼴이 통째로 Arial이었다.** 전역 CSS의 `body { font-family: Arial }`이 Geist 변수를 덮어쓰고 있었다. "디자인이 구리다"의 큰 부분이 이 한 줄이었다.
- **로그인해도 상단 메뉴가 그대로였다.** 메뉴는 서버에서 세션을 읽는데, 로그인 후 화면 전환만 하고 서버 트리를 새로 고치지 않았다. 2단계 인증·탈퇴 경로도 같은 문제였다.
- **회원가입 링크가 전부 404였다.** 실제 경로는 `/signup`인데 세 곳 모두 `/register`를 가리켰다.
- **설정 화면들이 도달 불가였다.** 위치·전화·2단계 인증·소셜 연결 페이지는 있었지만 어디서도 링크되지 않았다. 설정 허브를 만들고 메뉴·마이페이지에서 연결했다.
- **차단 상태가 거짓으로 보였다.** 상대가 나를 차단한 경우에도 "차단 해제" 버튼이 떠서, 눌러도 아무 일이 없고 전송은 계속 막혔다. 두 방향을 분리해 표시하도록 고쳤다.
- **채팅 사진 경로가 검증되지 않았다.** 클라이언트가 준 문자열을 그대로 저장하고 나중에 그 경로로 파일을 내려줬다. 업로드가 만든 형식만 허용하도록 막았다.

## 3. 새로 만든 기능

| 기능 | 요지 |
|---|---|
| 프로필 사진 | 업로드 시 EXIF 제거·400px webp 재인코딩. 없으면 닉네임 기반 그림. 메뉴·프로필·상품·채팅·거래 전반 반영 |
| 상품 숨기기/복원 | 삭제와 별개로 잠시 감추고 되돌리기. 내 상품 관리 화면에서 확인 |
| 가격 입력 | 입력 중 세 자리마다 쉼표, 복사·전송은 숫자만 |
| 직거래 약속 | 거래에 장소·시간을 정하고 거래방에 표시 |
| 거래 후기 | 정산 후 서로 한 번씩(좋아요·보통·별로 + 한마디), 공개 프로필에 요약·목록 |
| 구매한 상품 | 내 페이지에서만 보이는 구매 이력 |
| 채팅 나가기 | 내 목록에서만 사라지고, 상대가 새로 보내면 다시 나타남. 양쪽 다 나가면 휴면 → 관리자가 정리 |
| 읽음·안 읽은 수 | 마지막으로 본 시점 기준. 읽지 않고 나가면 읽음으로 처리되지 않음 |
| 신고 사유 선택 | 약속 불이행·무응답·무리한 흥정·욕설·사기 의심·스팸·부적절한 사진·기타 + 상세(선택) |
| 비속어 확인 | 보내기 전 한 번 물어보고, 그래도 보낼 수 있음. 서버는 관리자에게만 조용히 기록 |
| 연락처·계좌 탐지 | `영1영-5O14-6@977` 같은 우회 표기·한글 수사·은행명 조합까지 인식. 일반 안내는 표시, 우회·사기 이력은 관리자 통보 |
| 사기 이력 조회 | 상대 계좌·전화 확인(데모 흉내 조회) |
| 관리자 | 정지 해제, 휴면 채팅방 개별·일괄 정리, 자동 감지 배지 |

## 4. 검증

- 단위·컴포넌트 **1029개**, E2E **58개** 모두 통과. 타입 검사·프로덕션 빌드 통과. 한/영 문구 키 **477쌍** 일치.
- E2E에는 이번에 드러난 화면 결함을 다시 못 생기게 고정하는 테스트(`e2e/frontend.spec.ts`)를 새로 넣었다: 로그인 후 메뉴 변화, 가입 링크 유효성, 페이지 로드 시 콘솔 오류 없음, 없는 주소의 안내 화면.
- 데모 데이터는 `scripts/seed-demo-full.mjs` 하나로 상품·대화·거래(약속·정산·후기)·프로필 사진까지 채운다.

## 5. 남은 것

- 실시간 채팅(WebSocket)은 서버는 동작하지만 브라우저가 토큰을 보관하지 않아 연결하지 않는다. 지금은 REST로 주고받는다.
- 이메일·문자·소셜 로그인·결제·사기 이력 조회는 흉내(목)다. 어댑터만 바꾸면 실제 연동이 된다.
- 강제 탈퇴, 채팅 메시지 개별 삭제, 관리자 권한 세분화는 범위 밖으로 두었다.
