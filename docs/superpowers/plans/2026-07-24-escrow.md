# 에스크로(#5) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** 안전거래 송금 상태머신(요청→조정→보관→정산/반환), 금액 조정 협상, 상품 상태 원자적 연동, 분쟁 접수·관리자 조정, 감사 로그를 구현한다.

**Architecture:** `src/features/escrow/`에 상태머신(`status.ts`)·서비스(`service.ts`)·DB 표면(`db.ts`). Postgres(관계형, 상품·유저 강결합). 상품 연동은 `$transaction`. REST(Next API) 얇은 라우트. 돈은 목 보관(실 PG 없음).

**Tech Stack:** Next.js 16, Prisma 7, PostgreSQL, zod 4, Vitest + Playwright. 재사용: `requireActiveUser`/`requireAdmin`(RBAC, DB-fresh), `AppError`, `withErrorHandling`, `prisma`, 상품 상태머신 패턴(#3).

**설계:** `docs/superpowers/specs/2026-07-24-escrow-design.md`.

## Global Constraints
- **행위자 인가:** 전이별 행위자 강제 — `request`=구매자(판매자 본인 금지), `counter/accept/cancel/dispute`=참여자(수락은 비제안자), `fund/confirm`=구매자, `refund`=판매자, `resolve`=ADMIN. 참여자 아닌 제3자 조회·행동 403.
- **상태머신:** 유효 전이만(`INVALID_TRANSITION` 409), 종착(RELEASED/REFUNDED/CANCELLED) 재전이 불가.
- **상품 연동 원자성:** 에스크로+상품 상태는 한 `$transaction`. `fund` 시 상품 SELLING 재확인(이중 보관 방지, `PRODUCT_UNAVAILABLE` 409). fund→RESERVED, confirm→SOLD, refund→SELLING.
- **금액 무결성:** 서버 보관 금액(`escrow.amount`)만 정산. fund/confirm은 금액 입력 없음. 제안 금액 양수·상한(≤1e9). 수락은 비제안자만(자기 제안 자기 수락 금지, `CANNOT_ACCEPT_OWN` 400).
- **자기거래 금지:** 판매자 본인 상품 요청 불가(`SELF_TRADE` 400).
- **PII 없음:** 조회·목록에 이메일/전화/정확좌표 없음(상대=닉네임만). 감사 로그(EscrowEvent) 기록.
- REST 라우트 `requireActiveUser`(GUEST 401/SUSPENDED 403), resolve만 `requireAdmin`. 클라 에러 코드→카탈로그. UI 한/영 평어체.
- TypeScript strict. 짧은 한글 커밋, Co-Authored-By 금지. 브랜치 `feat/escrow`. Node PATH 없을 때 `/c/Program Files/nodejs`. DB 마이그레이션 체크섬 드리프트 주의(migrate deploy + DATABASE_URL export).
